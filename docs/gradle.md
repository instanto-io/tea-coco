# Gradle plugin

Plugin ID: **`io.instanto.tea-coco`**, version **`0.1.0-SNAPSHOT`**.
The implementation artifact is `io.instanto:tea-coco-gradle-plugin`; its plugin marker is published alongside it.
It works with TeaVM's `org.teavm.library` and `org.teavm` plugins, using their existing JUnit `Test` tasks.
It does not replace TeaVM's compiler, runner, browser selection or dependency versions.

## Resolve internal snapshots

Add the authenticated registry to **both** plugin management and normal dependency resolution. The plugin marker
is resolved during settings evaluation; `tea-coco` itself is resolved for the test and report tasks later.

In `settings.gradle.kts`:

```kotlin
pluginManagement {
    repositories {
        maven {
            url = uri("https://packages.instanto.io/api/packages/instanto-io/maven")
            credentials {
                username = System.getenv("FORGEJO_PACKAGE_USER")
                password = System.getenv("FORGEJO_PACKAGE_TOKEN")
            }
            content { includeGroupByRegex("io\\.instanto.*") }
        }
        gradlePluginPortal()
        mavenCentral()
    }
}
```

In `build.gradle.kts`:

```kotlin
plugins {
    java
    id("org.teavm.library") version "0.16.0" // or org.teavm for an application
    id("io.instanto.tea-coco") version "0.1.0-SNAPSHOT"
}
repositories {
    maven {
        url = uri("https://packages.instanto.io/api/packages/instanto-io/maven")
        credentials {
            username = System.getenv("FORGEJO_PACKAGE_USER")
            password = System.getenv("FORGEJO_PACKAGE_TOKEN")
        }
        content { includeGroupByRegex("io\\.instanto.*") }
    }
    mavenCentral()
}
dependencies {
    testImplementation("junit:junit:4.13.2")
}
tasks.test {
    useJUnit()
    // Keep existing TeaVM browser settings, or configure these for a new project.
    systemProperty("teavm.junit.js", "true")
    systemProperty("teavm.junit.js.runner", "browser-chrome")
}
teaCoco {
    // Defaults shown; no extra configuration is needed for src/main/java + test.
    enabled.set(true)
    testTask.set("test")
    sourceRoots.setFrom(layout.projectDirectory.dir("src/main/java"))
}
```

The Kotlin DSL extension is generated by Gradle from the plugin. Groovy builds use the same names, e.g.
`teaCoco { testTask = 'integrationTest'; sourceRoots.setFrom('../library/src/main/java') }`.
The selected task must already exist and have type `Test`.

Run `./gradlew teaCocoReport`. This runs the selected browser tests, writes
`build/reports/tea-coco/coverage.xml` and sibling `not-emitted.json`.
The selected test task also finalizes with reporting when run directly (`./gradlew test` or `check`).
A failing test remains a failed build even if a diagnostic report is produced.

## Configuration

| Property | Default | Purpose |
| --- | --- | --- |
| `enabled` | true, or `-PteaCoco.enabled=false` | Opt out of instrumentation/reporting without changing tests. |
| `version` | 0.1.0-SNAPSHOT | Matching tea-coco runtime/reporter version. |
| `testTask` | test | Existing Gradle `Test` task to instrument and collect. |
| `sourceRoots` | main source set's Java directories | Exact measured library/application sources; may point at another project. |
| `dataDirectory` | build/tea-coco/data | Dedicated baseline directory below the project's build directory. |
| `reportFile` | build/reports/tea-coco/coverage.xml | Sonar generic coverage output. |

The plugin adds tea-coco only to the selected test's runtime and its separate reporting configuration. Production
runtime dependencies are unchanged. It requires captured stdout in JUnit XML and enables it for the selected task.
The compiler's source roots and reporter's source roots come from the same setting.

A coverage invocation deliberately reruns the selected test task, disables its build-cache reuse and clears previous
coverage baselines/report. This prevents UUIDs or zero-hit inventories from one compilation mixing with another.
Other tasks keep their normal Gradle caching behavior. `dataDirectory` must be a dedicated subdirectory of
`buildDirectory` because the plugin clears it. Do not share it between projects or parallel builds.

## Scope of this first plugin

* Validated with Gradle **9.3.1**, build JDK **21**, TeaVM **0.16.0**, and real Chrome tests.
* Integrates one selected JUnit `Test` task per project; separate projects can each generate a report.
* TestKit checks configuration safety and disabled mode. The independent consumer smoke verifies both official
  TeaVM plugins, covered/uncovered/omitted lines, new baselines on repeat runs, failure-path collection, and disabled mode.
* Gradle configuration cache is explicitly unsupported for the instrumented test/report tasks in this first version.
* This is not automatic instrumentation of TeaVM's `generateJavaScript` tasks. Custom Playwright/application harnesses
  use the [compiler configuration and collection contract](consumer-guide.md#applications-with-playwright-or-another-browser-harness).
* No automatic Sonar plugin dependency or gate changes; set `sonar.coverageReportPaths` to the report path yourself.

TeaVM's plugins remain responsible for compilation and browser-test settings; see its
[official Gradle guide](https://teavm.org/docs/tooling/gradle.html). The plugin uses Gradle's standard
[Java Gradle Plugin development/publishing support](https://docs.gradle.org/current/userguide/java_gradle_plugin.html).

## Build locally

```sh
mvn -B -ntp -s central-settings.xml clean install
./gradlew check publishToMavenLocal
python3 scripts/smoke_gradle_consumer.py
```

For local development, use `mavenLocal()` in both repository blocks instead of the authenticated registry.
The Gradle wrapper is included; the core compiler extension and Maven reporter are built by the Maven reactor.
The Gradle adapter is built by the separate Gradle build in the same repository.
